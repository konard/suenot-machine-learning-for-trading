# Задаче-агностичная торговля -- Простое объяснение

## О чем это вообще? (Самое простое объяснение)

Представьте, что вы нанимаете работников в свою компанию:

- **Один человек** умеет только составлять отчёты
- **Второй** умеет только отвечать на звонки
- **Третий** умеет только вести переговоры
- **Четвёртый** умеет только анализировать данные

Вам приходится платить четверым зарплату, арендовать четыре рабочих места,
и самое неприятное -- они **не делятся друг с другом** тем, что узнали.

А теперь представьте, что вы нашли **одного универсального сотрудника**,
который умеет делать ВСЁ: и отчёты, и звонки, и переговоры, и анализ.
При этом знания из одной области помогают ему в другой!

**Задаче-агностичная торговля работает именно так:**
1. Создаётся ОДИН общий "мозг" (энкодер), который понимает рынок в целом
2. К нему подключаются лёгкие "насадки" (головы) для каждой конкретной задачи
3. Знания из одной задачи автоматически помогают решать другие
4. Результаты всех задач объединяются в единое торговое решение

Теперь заменим задачи офиса на **торговые задачи**:
- **Отчёты** = Предсказание тренда (рынок пойдёт вверх или вниз?)
- **Звонки** = Прогнозирование волатильности (насколько сильно будет "трясти"?)
- **Переговоры** = Определение режима рынка (тренд, боковик или хаос?)
- **Анализ** = Оценка риска (насколько опасно сейчас торговать?)

И у вас получилась задаче-агностичная торговля!

## Главная проблема, которую мы решаем

### Проблема "четырёх отдельных моделей"

Для торговли на бирже нужно ответить на четыре вопроса:

```
Вопрос 1: Куда пойдёт цена?       (тренд)
Вопрос 2: Насколько сильно?         (волатильность)
Вопрос 3: Какой сейчас режим рынка? (режим)
Вопрос 4: Насколько это рискованно? (риск)
```

Традиционный подход -- обучить ЧЕТЫРЕ отдельных модели:

```
Рыночные данные
     |
     +----> [Модель тренда]        --> "Цена пойдёт вверх"
     |      (100 000 параметров)
     |
     +----> [Модель волатильности]  --> "Волатильность высокая"
     |      (100 000 параметров)
     |
     +----> [Модель режима]         --> "Тренд восходящий"
     |      (100 000 параметров)
     |
     +----> [Модель риска]          --> "Риск средний"
            (100 000 параметров)

Итого: 400 000 параметров, и ни одна модель
не знает о том, чему научилась другая!
```

### Почему это плохо?

```
Проблема 1: РАСТОЧИТЕЛЬНОСТЬ
Каждая модель заново изучает одни и те же вещи.
Четырёхкратная работа впустую.

Проблема 2: РАЗОБЩЁННОСТЬ
Модели не общаются между собой.
Модель тренда нашла закономерность,
но модель риска о ней ничего не знает.

Проблема 3: ПРОТИВОРЕЧИВОСТЬ
Модель тренда говорит: "Покупай!"
Модель риска говорит: "Опасно!"
Кого слушать? Они обучались независимо.

Проблема 4: НЕГИБКОСТЬ
Хотите добавить пятую задачу?
Нужно обучать совершенно новую модель с нуля.
```

### Задаче-агностичное решение

```
Рыночные данные
     |
     v
+-----------------------------------------+
|     Универсальный энкодер (общий)       |
|     Вход -> [64] -> [32] -> [16]        |
|     (один раз изучает ВСЕ закономерности)|
+-----------------------------------------+
     |         |          |          |
     v         v          v          v
 [Голова]  [Голова]   [Голова]   [Голова]
 тренда   волатильн.  режима     риска
 (легкая)  (легкая)   (легкая)  (легкая)
     |         |          |          |
     v         v          v          v
  "Вверх"  "Высокая"  "Тренд"  "Средний"
     |         |          |          |
     +----+----+-----+----+----+-----+
          |          |          |
          v          v          v
    +-------------------------------+
    |      Объединение решений      |
    |   (взвешенное голосование)     |
    +-------------------------------+
               |
               v
      Единый торговый сигнал:
      "ПОКУПАТЬ, позиция 50%"

Итого: ~130 000 параметров вместо 400 000,
и все задачи делятся знаниями!
```

## Разбираем по шагам

### Шаг 1: Что такое "задаче-агностичный"?

"Агностичный" означает "не привязанный к конкретной задаче".

```
Задаче-СПЕЦИФИЧНАЯ модель:
"Я обучена ТОЛЬКО предсказывать тренд.
 Волатильность? Не знаю что это.
 Режим? Не моя работа."

Задаче-АГНОСТИЧНАЯ модель:
"Я понимаю рынок В ЦЕЛОМ.
 Тренд? Могу предсказать.
 Волатильность? Тоже могу.
 Режим? И это тоже.
 Мои знания УНИВЕРСАЛЬНЫ."
```

Это как разница между:
- **Переводчик только с английского** (задаче-специфичный)
- **Лингвист, понимающий структуру языков** (задаче-агностичный)

Лингвист может быстро освоить ЛЮБОЙ новый язык,
потому что понимает, как языки устроены В ЦЕЛОМ.

### Шаг 2: Архитектура -- Энкодер + Головы

Вся система состоит из двух частей:

```
ЧАСТЬ 1: УНИВЕРСАЛЬНЫЙ ЭНКОДЕР (тяжёлая умная часть)

Входные данные (19 признаков рынка)
     |
     v
+---------------------------+
|  Слой 1: 19 -> 64 нейрона |
|  Нормализация + активация  |
+---------------------------+
     |
     v
+---------------------------+
|  Слой 2: 64 -> 32 нейрона |
|  Нормализация + активация  |
+---------------------------+
     |
     v
+---------------------------+
|  Слой 3: 32 -> 16 нейронов|
|  Нормализация              |
+---------------------------+
     |
     v
Представление рынка (16 чисел)
= "сжатое понимание ситуации"


ЧАСТЬ 2: ЛЁГКИЕ ГОЛОВЫ (маленькие насадки)

Представление (16 чисел)
     |
     +---> Голова тренда:    16 -> 8 -> 3 (вверх/бок/вниз)
     |
     +---> Голова волатильн.: 16 -> 8 -> 1 (число)
     |
     +---> Голова режима:     16 -> 8 -> 4 (тренд/откат/волат./спокойн.)
     |
     +---> Голова риска:      16 -> 8 -> 3 (низкий/средний/высокий)
```

Ключевая идея: энкодер ОДИН, а головы -- лёгкие и заменяемые.
Хотите добавить новую задачу? Подключите ещё одну голову!

### Шаг 3: Какие признаки использует модель?

Модель анализирует 19 признаков рыночных данных, сгруппированных по категориям:

```
+------------------+--------------------------------------+
| Категория        | Признаки                             |
+------------------+--------------------------------------+
| Доходность (2)   | Дневная доходность,                  |
|                  | пятидневная доходность               |
+------------------+--------------------------------------+
| Импульс (3)      | RSI (индекс силы),                   |
|                  | MACD сигнал,                         |
|                  | пересечение скользящих средних       |
+------------------+--------------------------------------+
| Волатильность (3)| Реализованная волатильность,          |
|                  | позиция в полосах Боллинджера,       |
|                  | ATR к цене (размах колебаний)        |
+------------------+--------------------------------------+
| Объём (2)        | Отношение объёма (текущий/средний),   |
|                  | тенденция объёма                      |
+------------------+--------------------------------------+
| Свечи (3)        | Отношение тела, верхняя тень,         |
|                  | нижняя тень                           |
+------------------+--------------------------------------+
| Диапазон (2)     | Процент диапазона,                    |
|                  | позиция закрытия                      |
+------------------+--------------------------------------+
| Тренд (2)        | Сила тренда (наклон),                 |
|                  | устойчивость тренда (доля дней роста)|
+------------------+--------------------------------------+
| Распределение (2)| Асимметрия доходности,               |
|                  | эксцесс (тяжёлые хвосты)             |
+------------------+--------------------------------------+
```

Энкодер берёт ВСЕ 19 признаков и "сжимает" их в 16 чисел --
компактное представление текущего состояния рынка.

### Шаг 4: Четыре торговые задачи

```
ЗАДАЧА 1: ПРЕДСКАЗАНИЕ ТРЕНДА
  Вопрос: Куда пойдёт цена?
  Ответы: Вверх / Вбок / Вниз (3 класса)

ЗАДАЧА 2: ПРОГНОЗ ВОЛАТИЛЬНОСТИ
  Вопрос: Насколько сильно будет колебаться?
  Ответ:  Число (например, 0.35)

ЗАДАЧА 3: ОПРЕДЕЛЕНИЕ РЕЖИМА РЫНКА
  Вопрос: Как ведёт себя рынок сейчас?
  Ответы: Тренд / Откат к среднему / Волатильный / Спокойный (4 класса)

ЗАДАЧА 4: ОЦЕНКА РИСКА
  Вопрос: Насколько опасно сейчас торговать?
  Ответы: Низкий / Средний / Высокий (3 класса)
```

### Шаг 5: Объединение решений (Decision Fusion)

После того как все четыре головы дали свои ответы,
нужно объединить их в ОДНО торговое решение:

```
ПРИМЕР ОБЪЕДИНЕНИЯ РЕШЕНИЙ:

Голова тренда (вес 0.35):
  Вверх: 60%   Вбок: 30%   Вниз: 10%
  --> Сигнал: +0.175 (бычий)

Голова волатильности (вес 0.20):
  Прогноз: 0.30 (умеренная)
  --> Уверенность: 91%

Голова режима (вес 0.25):
  Тренд: 50%   Откат: 20%   Волат: 20%   Спокойн: 10%
  --> Режим: "Тренд" --> усиливаем сигнал (x1.2)

Голова риска (вес 0.20):
  Низкий: 60%   Средний: 30%   Высокий: 10%
  --> Корректировка: 95% (риск невысок)

ИТОГО:
  Сигнал: +0.20, уверенность: 72%, режим: Тренд
  --> РЕШЕНИЕ: ПОКУПАТЬ, размер позиции 50%
```

### Шаг 6: Торговый сигнал

Финальный сигнал определяется по таблице:

```
+-------------------+----------------+-----------+
| Значение сигнала  |  Тип           | Позиция   |
+-------------------+----------------+-----------+
| >= +0.40          | Сильная покупка | 100% лонг |
| >= +0.15          | Покупка         |  50% лонг |
| -0.15 ... +0.15   | Ожидание        | Без позиц.|
| <= -0.15          | Продажа         |  50% шорт |
| <= -0.40          | Сильная продажа | 100% шорт |
+-------------------+----------------+-----------+
```

## Конкретный торговый пример

### Сценарий: Утро на крипторынке

```
Время: 09:00 UTC, понедельник
Актив: BTC/USDT на Bybit
Цена: 65 000 USDT
Данные за последние 20 дней собраны.
```

**Что видит каждая голова:**

```
ГОЛОВА ТРЕНДА:
  RSI = 0.65 (умеренно бычий), MACD положительный
  --> Вверх 55%, Вбок 35%, Вниз 10%

ГОЛОВА ВОЛАТИЛЬНОСТИ:
  Реализованная волатильность = 0.25, ATR растёт
  --> Прогноз: 0.32 (умеренная, но растёт)

ГОЛОВА РЕЖИМА:
  Сила тренда высокая, устойчивость = 0.7
  --> Тренд 60%, Откат 15%, Волатильный 20%, Спокойный 5%

ГОЛОВА РИСКА:
  Эксцесс нормальный, объём стабильный
  --> Низкий 50%, Средний 40%, Высокий 10%
```

**Объединение:**

```
Шаг 1: Сигнал тренда    = 0.35 * (0.55 - 0.10) = +0.1575
Шаг 2: Уверенность      = 1 - 0.32^2           = 0.8976
Шаг 3: Множитель режима  = 1.2 (тренд усиливает)
Шаг 4: Множитель риска   = 1 - 0.10 * 0.5       = 0.95

Финальный сигнал: +0.1575 * 1.2 * 0.95 = +0.18
+0.18 >= +0.15 --> ПОКУПКА, позиция 50%

ИТОГОВОЕ РЕШЕНИЕ:
+-------------------------------------------+
| Действие:    ПОКУПАТЬ BTC/USDT             |
| Позиция:     50% от максимальной           |
| Стоп-лосс:   63 700 USDT (-2%)            |
| Тейк-профит: 68 250 USDT (+5%)            |
+-------------------------------------------+
```

## Проблема конфликта градиентов (простым языком)

Когда мы обучаем одну модель решать несколько задач одновременно,
возникает проблема: задачи могут "тянуть модель в разные стороны".

### Аналогия: Перетягивание каната

```
Представьте, что четыре человека тянут одну верёвку:

         Задача тренда
              ^
              |
Задача   <----+----> Задача
режима        |      волатильности
              |
              v
         Задача риска

Если все тянут в разные стороны -- верёвка не двигается!
Модель "застревает" и ничему не учится.
```

### Решение: Гармонизация градиентов

```
Метод 1: GradNorm (нормализация градиентов)
  Идея: задачам, которые учатся медленно,
  дать больше "силы" (больший вес).
  Результат: все задачи прогрессируют РАВНОМЕРНО.

Метод 2: PCGrad (проекция конфликтующих градиентов)
  Идея: если два градиента толкают модель
  в противоположных направлениях -- убрать
  конфликтующую часть, оставить полезную.

Метод 3: Взвешивание по неопределённости
  Идея: задачам, в которых модель "не уверена",
  дать меньший вес. Уверенным -- больший.
```

## Сравнительные таблицы

### Задаче-специфичный vs задаче-агностичный подход

```
+---------------------+---------------------------+---------------------------+
| Характеристика      | Отдельные модели          | Единая модель             |
+---------------------+---------------------------+---------------------------+
| Параметры           | 4 полные модели           | 1 энкодер + 4 легкие      |
|                     | (400 000)                 | головы (~130 000)          |
+---------------------+---------------------------+---------------------------+
| Извлечение          | Каждая учит свои          | Общие признаки,           |
| признаков           | признаки заново           | один раз                   |
+---------------------+---------------------------+---------------------------+
| Передача знаний     | Нет                       | Автоматическая            |
+---------------------+---------------------------+---------------------------+
| Время вычислений    | 4 прямых прохода          | 1 кодирование +           |
|                     |                           | 4 прохода через головы    |
+---------------------+---------------------------+---------------------------+
| Согласованность     | Независимые сигналы       | Согласованные решения     |
+---------------------+---------------------------+---------------------------+
| Новая задача        | Обучать с нуля            | Подключить новую голову   |
+---------------------+---------------------------+---------------------------+
```

### Когда использовать какой подход?

```
+------------------------------------+-------------------------------------+
| Используйте ОТДЕЛЬНЫЕ модели,     | Используйте ЕДИНУЮ модель,         |
| когда:                             | когда:                              |
+------------------------------------+-------------------------------------+
| Задачи совершенно не связаны      | Задачи анализируют одни данные     |
| (торговля + бухгалтерия)           | (тренд + волатильность + режим)     |
+------------------------------------+-------------------------------------+
| Нужна максимальная точность       | Нужен баланс скорости и точности   |
| только для ОДНОЙ задачи           | для НЕСКОЛЬКИХ задач                |
+------------------------------------+-------------------------------------+
| Ресурсы не ограничены             | Ресурсы ограничены                  |
+------------------------------------+-------------------------------------+
| Данные для задач совершенно разные | Данные пересекаются (одни свечи)    |
+------------------------------------+-------------------------------------+
```

## Почему Rust? Почему Bybit?

### Почему Rust?

Представьте языки программирования как транспорт:

```
+-----------+----------+-------------------------------------+
| Транспорт | Язык     | Характеристики                      |
+-----------+----------+-------------------------------------+
| Велосипед | Python   | Просто, доступно, но медленно       |
| Гоночная  | Rust     | Быстро, безопасно, надёжно          |
| машина    |          |                                      |
| Мотоцикл  | C/C++    | Очень быстро, но легко разбиться    |
+-----------+----------+-------------------------------------+
```

Для торговли нужна "гоночная машина" (Rust):
- Решения за миллисекунды (скорость)
- Не "падает" во время торгов (безопасность)
- Одинаковый результат при одинаковых данных (предсказуемость)
- Обрабатывает тысячи обновлений в секунду (пропускная способность)

### Почему Bybit?

Bybit -- это наша "торговая площадка":

```
* Данные в реальном времени (свежие рыночные данные)
* Множество торговых пар (BTC, ETH, 100+ монет)
* Бессрочные фьючерсы (прибыль в любом направлении)
* Тестовая сеть (практика без реальных денег)
* Хорошая документация API (понятные инструкции)
* Низкая задержка (быстрое исполнение)
```

## Проверь себя!

### Вопрос 1:
Что означает "задаче-агностичный" в контексте торговли?

```
А) Модель не верит в существование задач
Б) Модель создана для одной конкретной задачи
В) Модель не привязана к конкретной задаче
   и может решать несколько задач одновременно
Г) Модель отказывается решать задачи
```

<details>
<summary>Ответ</summary>

**В)** -- "Агностичный" означает "не привязанный", "нейтральный".
Задаче-агностичная модель изучает универсальные представления,
полезные для ЛЮБОЙ торговой задачи, а не только для одной конкретной.

</details>

### Вопрос 2:
Из каких двух главных частей состоит задаче-агностичная модель?

```
А) Входной слой и выходной слой
Б) Универсальный энкодер и лёгкие головы задач
В) База данных и интерфейс пользователя
Г) Тренировочный набор и тестовый набор
```

<details>
<summary>Ответ</summary>

**Б)** -- Энкодер (общий "мозг") извлекает универсальное представление
рынка, а лёгкие головы декодируют это представление для конкретной цели:
тренд, волатильность, режим или риск.

</details>

### Вопрос 3:
Почему одна общая модель лучше четырёх отдельных?

```
А) Потому что она использует больше данных
Б) Потому что она медленнее, но точнее
В) Потому что задачи делятся знаниями, экономя
   ресурсы и обеспечивая согласованность решений
Г) Потому что её проще программировать
```

<details>
<summary>Ответ</summary>

**В)** -- Главные преимущества: (1) общие признаки извлекаются один раз
вместо четырёх, (2) знания передаются между задачами автоматически,
(3) решения согласованы, а не противоречивы, (4) добавить новую задачу --
это просто подключить ещё одну лёгкую голову.

</details>

### Вопрос 4:
Что такое "гармонизация градиентов" и зачем она нужна?

```
А) Метод визуализации данных
Б) Способ балансировки обучения разных задач,
   чтобы ни одна не доминировала над другими
В) Алгоритм сортировки данных
Г) Техника сжатия нейронной сети
```

<details>
<summary>Ответ</summary>

**Б)** -- При обучении нескольких задач одновременно их градиенты
могут конфликтовать (тянуть модель в разные стороны). Гармонизация
(GradNorm, PCGrad) решает эту проблему, обеспечивая равномерный
прогресс по всем задачам.

</details>

### Вопрос 5:
Сколько торговых задач решает модель из этой главы?

```
А) Одну -- предсказание тренда
Б) Две -- тренд и волатильность
В) Четыре -- тренд, волатильность, режим и риск
Г) Десять различных задач
```

<details>
<summary>Ответ</summary>

**В)** -- Модель решает четыре задачи: (1) предсказание тренда
(вверх/вбок/вниз), (2) прогноз волатильности (число), (3) определение
режима рынка (тренд/откат/волатильный/спокойный), (4) оценка риска
(низкий/средний/высокий). Все используют ОДНО общее представление.

</details>

### Вопрос 6:
Что такое "объединение решений" (Decision Fusion)?

```
А) Удаление ненужных решений
Б) Выбор случайного решения из четырёх
В) Взвешенное объединение предсказаний всех голов
   в единый торговый сигнал
Г) Копирование решения одной головы
```

<details>
<summary>Ответ</summary>

**В)** -- Объединение решений -- это процесс, при котором предсказания
всех четырёх голов объединяются с учётом весов в один финальный
торговый сигнал: покупать, продавать или ждать.

</details>

### Вопрос 7:
Если сигнал модели равен +0.25, какое решение она примет?

```
А) Сильная покупка (100% лонг)
Б) Покупка (50% лонг)
В) Ожидание (без позиции)
Г) Продажа (50% шорт)
```

<details>
<summary>Ответ</summary>

**Б)** -- Согласно таблице сигналов: значение +0.25 попадает в диапазон
">= +0.15", что соответствует сигналу "Покупка" с размером позиции 50%
лонг. Для "Сильной покупки" нужно значение >= +0.40.

</details>

## Итоги

**Задаче-агностичная торговля** -- это подход, при котором:

- Создаётся ОДИН универсальный энкодер, который понимает рынок в целом
- К нему подключаются ЛЁГКИЕ головы для каждой конкретной задачи
- Знания АВТОМАТИЧЕСКИ передаются между задачами
- Решения всех задач ОБЪЕДИНЯЮТСЯ в единый торговый сигнал
- Гармонизация градиентов обеспечивает РАВНОМЕРНОЕ обучение всех задач

Ключевое преимущество: вместо четырёх разобщённых моделей вы получаете
одну согласованную систему, где общее понимание рынка служит фундаментом
для всех торговых решений -- быстрее, экономнее, согласованнее.
