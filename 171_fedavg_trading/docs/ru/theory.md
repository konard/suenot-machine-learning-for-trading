# Теория Federated Averaging (FedAvg)

Алгоритм FedAvg, предложенный McMahan et al. в 2017 году, является стандартом де-факто для федеративного обучения. Его основная цель — минимизировать объем передаваемых данных при сохранении высокой точности модели.

## Математическая постановка

Мы хотим минимизировать функцию потерь $f(w)$, распределенную по $K$ клиентам:
$$\min_w f(w) = \sum_{k=1}^K \frac{n_k}{n} F_k(w)$$
Где $F_k(w)$ — локальная функция потерь клиента $k$, а $n_k$ — количество данных у этого клиента.

## Алгоритм работы

1. **Сервер** отправляет текущие веса $w_t$ выбранным клиентам.
2. **Клиенты** инициализируют свою локальную модель: $w_t^k = w_t$.
3. **Локальное обучение**: Каждый клиент выполняет $E$ эпох градиентного спуска (SGD) на своих данных:
   $$w_{t+1}^k = w_t^k - \eta \nabla F_k(w_t^k)$$
4. **Агрегация**: Сервер собирает обновленные веса $w_{t+1}^k$ и усредняет их:
   $$w_{t+1} = \sum_{k=1}^K \frac{n_k}{n} w_{t+1}^k$$

## Ключевые параметры

- **$B$ (Batch Size)**: Размер локального батча.
- **$E$ (Local Epochs)**: Количество локальных эпох. Если $E$ велико, клиенты делают больше вычислений между раундами связи, что ускоряет обучение, но может привести к "отклонению" (drift) модели, если данные сильно различаются (Non-IID).
- **$C$ (Selection Fraction)**: Доля клиентов, участвующих в каждом раунде.

## Проблема Non-IID данных в трейдинге

В финансах данные почти никогда не бывают распределены идентично (Independent and Identically Distributed).
- Один клиент может торговать только на рынке криптовалют (высокая волатильность).
- Другой клиент — только на рынке облигаций (низкая волатильность).

FedAvg может "страдать" от этого разнообразия. Глобальная модель рискует стать "средней по больнице", которая плохо работает на специфических рынках. Решению этой проблемы посвящены следующие главы (FedProx, Scaffold и др.).

## Преимущества для безопасности

FedAvg не передает градиенты на каждом шаге, а передает только итоговые веса раз в несколько эпох. Это значительно усложняет задачу "восстановления" исходных данных злоумышленником через обратный инжиниринг признаков (Inference Attack).
