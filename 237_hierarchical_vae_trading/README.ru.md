# Глава 237: Иерархический VAE для трейдинга

## 1. Введение — многомасштабные латентные представления для финансовых рынков

Финансовые рынки работают одновременно на нескольких временных масштабах. Внутридневные колебания цен отражают микроструктурный шум и краткосрочную динамику потока ордеров. Дневные и недельные доходности отражают эффекты моментума, неожиданности в отчётах компаний и ротацию секторов. Месячные и квартальные паттерны раскрывают макроэкономические циклы, кредитные условия и структурные сдвиги в настроении инвесторов. Торговая модель, улавливающая только один масштаб, неизбежно упускает критически важную информацию, доступную на других.

Стандартные вариационные автокодировщики (VAE) изучают единое латентное пространство, которое должно сжать всю вариацию — от тикового шума до макрорежимных сдвигов — в плоское представление. Это вынуждает модель идти на некомфортные компромиссы: латентное пространство, достаточно большое для захвата макроструктуры, тратит ёмкость на шум, а настроенное на мелкозернистые паттерны не может представить медленно меняющиеся тренды.

**Иерархический VAE (HVAE)** решает эту фундаментальную проблему, организуя латентное пространство в несколько уровней, каждый из которых работает на разном масштабе абстракции. Верхние уровни захватывают медленно меняющуюся глобальную структуру (рыночные режимы, направление тренда, режимы волатильности), а нижние уровни кодируют быстро меняющиеся локальные детали (дневные паттерны доходности, краткосрочное среднее возвращение, микроструктурные эффекты). Уровни взаимодействуют через генеративный путь сверху вниз: латентные переменные высокого уровня задают контекст, а нижние уровни уточняют детали в рамках этого контекста.

Эта архитектура вдохновлена **Ladder VAE** (Sønderby и др., 2016), который продемонстрировал, что иерархические латентные переменные с путями вывода сверху вниз значительно улучшают выразительность и стабильность обучения глубоких генеративных моделей. В трейдинге это означает модели, способные одновременно рассуждать о «в каком мы режиме?» (верхний уровень) и «какой конкретный паттерн доходности происходит сегодня?» (нижний уровень), с когерентным взаимодействием между этими масштабами.

В этой главе мы разработаем полную реализацию Иерархического VAE на Rust, интегрируем её с рыночными данными с Bybit и продемонстрируем, как многомасштабные латентные представления улучшают качество генерируемых сценариев и полезность изученных представлений для торговых решений.

## 2. Математическое обоснование

### Иерархическая генеративная модель

Стандартный VAE использует единственную латентную переменную z и факторизует совместное распределение как:

```
p(x, z) = p(z) * p(x|z)
```

Иерархический VAE вводит L уровней латентных переменных z_1, z_2, ..., z_L, где z_L — самый высокий (наиболее абстрактный) уровень. Генеративная модель факторизуется сверху вниз:

```
p(x, z_1, ..., z_L) = p(z_L) * prod_{l=L-1}^{1} p(z_l | z_{l+1}) * p(x | z_1)
```

Каждое условное распределение p(z_l | z_{l+1}) параметризуется нейронной сетью, которая принимает латентную переменную более высокого уровня и выдаёт параметры (среднее, дисперсию) гауссовского распределения для текущего уровня. Приор на верхнем уровне p(z_L) обычно является стандартным гауссианом N(0, I).

### Иерархическая модель вывода

Приближённое апостериорное распределение (кодировщик) отражает генеративную структуру, но работает снизу вверх, затем комбинируется с информацией сверху вниз:

**Проход снизу вверх:** Детерминированный кодировщик обрабатывает вход x через серию слоёв, создавая промежуточные представления d_1, d_2, ..., d_L на каждом уровне.

**Проход сверху вниз с выводом:** Начиная с верхнего уровня, на каждом уровне l:

```
q(z_l | z_{l+1}, x) = N(z_l; mu_q_l, sigma_q_l)
```

где параметры mu_q_l и sigma_q_l вычисляются путём комбинирования:
- Представления снизу вверх d_l (из данных)
- Представления сверху вниз от z_{l+1} (от верхних уровней)

Это комбинирование обычно выполняется через слияние, взвешенное по точности:

```
mu_q_l = (mu_bu_l / sigma_bu_l^2 + mu_td_l / sigma_td_l^2) / (1/sigma_bu_l^2 + 1/sigma_td_l^2)
sigma_q_l^2 = 1 / (1/sigma_bu_l^2 + 1/sigma_td_l^2)
```

где mu_bu_l, sigma_bu_l получены из пути снизу вверх, а mu_td_l, sigma_td_l — из генеративной модели сверху вниз.

### Иерархический ELBO

Нижняя граница свидетельства для иерархической модели декомпозируется как:

```
ELBO = E_q[log p(x|z_1)] - sum_{l=1}^{L} KL(q(z_l | z_{l+1}, x) || p(z_l | z_{l+1}))
```

Это сумма члена реконструкции (насколько хорошо латентные переменные нижнего уровня восстанавливают вход) и L членов KL-дивергенции (по одному на уровень, измеряющих, насколько модель вывода отклоняется от генеративного приора на каждом уровне).

### Почему иерархия помогает: аргумент распределения информации

Ключевое наблюдение состоит в том, что иерархия позволяет модели эффективно распределять информацию по уровням. Без иерархии штраф KL вынуждает всю информацию проходить через одно узкое место, что приводит к двум режимам отказа:

1. **Коллапс апостериорного распределения:** Модель полностью игнорирует латентные переменные, полагаясь исключительно на ёмкость декодировщика. Член KL сдвигает q(z|x) к p(z), делая z неинформативным.

2. **Информационная перегрузка:** Слишком много информации упаковывается в единое латентное пространство, делая представления запутанными и трудными для использования.

С иерархией каждый уровень может специализироваться:
- Высокие уровни захватывают широкую структуру с низкой стоимостью KL (эта информация разделяется между многими точками данных)
- Низкие уровни захватывают детали, специфичные для экземпляра, с более высокой стоимостью KL, но соответственно более высокой выгодой реконструкции

Это естественное распределение информации создаёт представления, интерпретируемые на каждом уровне — именно то, что нам нужно для многомасштабного торгового анализа.

### KL-отжиг и свободные биты

Обучение иерархических VAE требует тщательного обращения с членами KL для предотвращения коллапса апостериорного распределения на отдельных уровнях. Две техники являются стандартными:

**KL-отжиг:** Коэффициент разогрева beta увеличивается от 0 до 1 в течение первой части обучения:

```
Loss = Reconstruction + beta * sum(KL_l)
```

Это позволяет модели сначала изучить полезные представления, а затем постепенно регуляризировать их.

**Свободные биты:** Минимальное значение KL lambda применяется для каждого уровня:

```
KL_l_effective = max(KL_l, lambda)
```

Это предотвращает коллапс любого уровня до приора, гарантируя, что все уровни несут информацию.

## 3. Многомасштабная финансовая интерпретация

### Соответствие уровней торговым горизонтам

В нашей реализации с L=3 уровнями:

**Уровень 3 (Верхний — Макромасштаб):** Захватывает рыночный режим и направление тренда. Латентные переменные на этом уровне меняются медленно и соответствуют макросостояниям: бычьи/медвежьи рынки, режимы высокой/низкой волатильности, среды risk-on/risk-off. Эти переменные имеют наибольшую автокорреляцию и наиболее полезны для решений по стратегическому распределению.

**Уровень 2 (Средний — Тактический масштаб):** Захватывает среднесрочные паттерны, такие как персистентность моментума, циклы среднего возвращения и ротация секторов. Эти переменные меняются на еженедельной-ежемесячной основе и релевантны для тактических торговых решений: размер позиций, секторные наклоны и корректировка рисков.

**Уровень 1 (Нижний — Масштаб исполнения):** Захватывает дневные паттерны доходности, краткосрочную кластеризацию волатильности и микроструктурные эффекты. Эти переменные меняются быстро и наиболее релевантны для тайминга сделок, оптимизации исполнения и краткосрочного хеджирования.

### Генерация с контролем масштаба

Иерархическая структура позволяет мощную форму контролируемой генерации. Фиксируя латентные переменные верхнего уровня и семплируя нижние уровни, мы можем генерировать разнообразные дневные сценарии доходности, которые все разделяют один макрорежим. Это гораздо более нюансированно, чем однорежимное обуславливание CVAE — мы можем указать не просто «медвежий рынок», а конкретный тип медвежьего рынка (постепенное снижение vs крах, секторно-специфичный vs широкомасштабный).

И наоборот, фиксируя нижние уровни и варьируя верхний, мы можем исследовать, как один и тот же локальный паттерн разворачивается в разных макроусловиях — полезно для стресс-тестирования при смене режима.

## 4. Торговые приложения

### Многомасштабная оценка рисков

Традиционные модели риска работают на одном масштабе, обычно дневных доходностей. Это упускает важные межмасштабные взаимодействия:

- Портфель может казаться безопасным на дневном уровне, при этом накапливая опасные макроэкспозиции
- Краткосрочное хеджирование может быть адекватным для нормальных условий, но провалиться при переходах между режимами

Многомасштабные представления HVAE позволяют оценивать риск на каждом уровне независимо и в комбинации:

1. **Макрориск (Уровень 3):** Вероятность перехода между режимами, ожидаемая продолжительность текущего режима
2. **Тактический риск (Уровень 2):** Вероятность разворота моментума, риск секторной концентрации
3. **Риск исполнения (Уровень 1):** Краткосрочное прогнозирование волатильности, риск ликвидности

### Иерархическая генерация сценариев

Для стресс-тестирования иерархическая структура позволяет генерировать сценарии на каждом уровне иерархии:

1. Фиксировать стрессовое макросостояние на Уровне 3 (например, рецессия)
2. Семплировать разнообразные тактические паттерны на Уровне 2 (разные пути через рецессию)
3. Для каждого тактического пути генерировать несколько дневных последовательностей доходности на Уровне 1

Это создаёт дерево сценариев с осмысленной структурой, а не плоскую коллекцию независимых путей.

### Торговые сигналы из латентных факторов

Каждый уровень иерархии производит латентные переменные, которые могут служить торговыми сигналами:

- **Сдвиги Уровня 3** → Сигналы смены режима для стратегической ребалансировки
- **Тренды Уровня 2** → Сигналы моментума/среднего возвращения для тактической торговли
- **Паттерны Уровня 1** → Краткосрочные альфа-сигналы для тайминга исполнения

Иерархическая структура гарантирует, что эти сигналы естественно ортогональны — каждый уровень захватывает вариацию, не объяснённую уровнями выше.

## 5. Проектирование архитектуры

### Кодировщик снизу вверх

Кодировщик снизу вверх обрабатывает входные признаки через серию слоёв с возрастающей абстракцией. Каждый слой создаёт детерминированное представление d_l, захватывающее информацию на соответствующем масштабе:

```
d_1 = ReLU(W_1 * x + b_1)          # Локальные паттерны
d_2 = ReLU(W_2 * d_1 + b_2)        # Среднемасштабные паттерны
d_3 = ReLU(W_3 * d_2 + b_3)        # Глобальные паттерны
```

На каждом уровне d_l используется для создания параметров снизу вверх для приближённого апостериорного распределения.

### Декодировщик сверху вниз со стохастическими слоями

Путь сверху вниз начинается с верхнего уровня и работает вниз. На каждом уровне:

1. Комбинирование контекста сверху вниз с информацией снизу вверх
2. Семплирование латентных переменных из объединённого распределения
3. Передача семпла на следующий уровень ниже

```
z_3 ~ q(z_3 | d_3)                            # Верхний уровень: только снизу вверх
z_2 ~ q(z_2 | merge(d_2, transform(z_3)))     # Средний: слияние обоих путей
z_1 ~ q(z_1 | merge(d_1, transform(z_2)))     # Нижний: слияние обоих путей
x_recon = decode(z_1)                          # Реконструкция из нижнего уровня
```

### Операция слияния

Операция слияния комбинирует параметры гауссианов снизу вверх и сверху вниз используя взвешивание по точности. Для двух гауссовских распределений N(mu_1, sigma_1^2) и N(mu_2, sigma_2^2) объединённое распределение:

```
precision = 1/sigma_1^2 + 1/sigma_2^2
mu_merged = (mu_1/sigma_1^2 + mu_2/sigma_2^2) / precision
sigma_merged^2 = 1 / precision
```

Это гарантирует, что уровень с более точной (меньшей дисперсией) информацией доминирует в объединённом распределении — принципиальный способ комбинирования информации, основанной на данных, и информации, основанной на модели.

## 6. Пошаговое описание реализации на Rust

Наша реализация на Rust предоставляет полную систему Иерархического VAE со следующими компонентами:

### Основная архитектура

**HierarchicalEncoder** реализует проход снизу вверх, преобразуя входные признаки через несколько слоёв для создания детерминированных представлений на каждом уровне. Представление каждого уровня используется для вычисления параметров среднего и логарифма дисперсии снизу вверх для приближённого апостериорного распределения.

**HierarchicalDecoder** реализует генеративный путь сверху вниз. На каждом уровне (начиная с верхнего) он вычисляет параметры приора сверху вниз, объединяет их с параметрами снизу вверх используя взвешивание по точности, семплирует латентные переменные и передаёт их на следующий уровень. Итоговая реконструкция создаётся из латентных переменных нижнего уровня.

**PrecisionWeightedMerge** комбинирует гауссовские распределения снизу вверх и сверху вниз на каждом уровне, взвешивая каждое по его точности (обратной дисперсии). Это принципиальное комбинирование позволяет модели балансировать между свидетельствами на основе данных (снизу вверх) и структурными приорами (сверху вниз).

### Стратегия обучения

Обучение включает:

1. **Проход снизу вверх:** Кодирование входа для создания детерминированных представлений на всех уровнях
2. **Вывод сверху вниз:** Начиная с верха, объединение информации снизу вверх и сверху вниз, семплирование латентных переменных на каждом уровне
3. **Реконструкция:** Декодирование из латентных переменных нижнего уровня
4. **Вычисление потерь:** MSE реконструкции + KL-дивергенция на каждом уровне
5. **KL-отжиг:** Постепенное увеличение веса членов KL в течение эпох обучения для предотвращения коллапса
6. **Обновление параметров:** Численный градиентный спуск (демонстрация; промышленные системы должны использовать автодифференцирование)

### Диагностика по уровням

Мы мониторим KL-дивергенцию на каждом уровне отдельно. Здоровое обучение показывает:
- Уровень 3 (верхний): Умеренная KL — захватывает информацию о глобальном режиме
- Уровень 2 (средний): Умеренная KL — захватывает тактические паттерны
- Уровень 1 (нижний): Более высокая KL — захватывает мелкозернистые детали

Если какой-либо уровень показывает KL, близкую к нулю, это указывает на коллапс апостериорного распределения на этом уровне, который можно устранить, увеличив порог свободных битов.

## 7. Интеграция с Bybit

Наша реализация получает реальные рыночные данные через API Bybit, в частности данные кэндлстиков (kline) BTCUSDT. Интеграция работает следующим образом:

1. **Endpoint API:** Мы используем `https://api.bybit.com/v5/market/kline` для получения исторических данных OHLCV.

2. **Обработка данных:** Необработанные данные кэндлстиков преобразуются в логарифмические доходности, которые служат входными признаками HVAE. Мы вычисляем доходности из цен закрытия и нормализуем их для численной стабильности.

3. **Многомасштабное построение признаков:** Каждый обучающий образец состоит из окна нормализованных доходностей. Иерархический VAE внутренне учится декомпозировать это окно на многомасштабные компоненты — архитектура обрабатывает разделение масштабов автоматически через иерархию латентных переменных.

4. **Оценка режимов:** После обучения мы определяем рыночные режимы с помощью скользящей статистики и оцениваем, коррелируют ли латентные переменные верхнего уровня HVAE с обнаруженными режимами, подтверждая, что иерархия изучила осмысленную многомасштабную структуру.

Этот конвейер обеспечивает полностью автоматизированный рабочий процесс от необработанных рыночных данных до обученного Иерархического VAE, не требуя ручной подготовки данных или явной многомасштабной инженерии признаков.

## 8. Ключевые выводы

1. **Иерархические VAE организуют латентное пространство в несколько уровней**, каждый из которых захватывает вариацию на разном масштабе абстракции — от макрорежимной структуры до мелкозернистых дневных паттернов.

2. **Иерархический ELBO декомпозируется на поуровневые члены KL**, позволяя модели эффективно распределять информацию по масштабам. Высокие уровни захватывают широко разделяемую структуру; низкие уровни захватывают детали, специфичные для экземпляра.

3. **Слияние, взвешенное по точности**, информации снизу вверх (на основе данных) и сверху вниз (на основе модели) на каждом уровне обеспечивает принципиальный механизм комбинирования свидетельств по всей иерархии.

4. **Многомасштабная генерация** позволяет нюансированное построение сценариев: фиксация макрорежима на верхнем уровне, затем генерация разнообразных тактических и дневных путей под ним. Это создаёт деревья сценариев, а не плоские коллекции.

5. **KL-отжиг и свободные биты** — необходимые техники обучения, предотвращающие коллапс апостериорного распределения — режим отказа, при котором отдельные уровни иерархии становятся неинформативными.

6. **Торговые приложения охватывают несколько горизонтов**: латентные переменные верхнего уровня предоставляют сигналы режима для стратегического распределения, среднего уровня — информацию для тактического позиционирования, нижнего уровня — поддержку тайминга исполнения.

7. **Реализация на Rust** обеспечивает производительность, необходимую для многомасштабного анализа в реальном времени, а интеграция с Bybit позволяет создать полный конвейер от реальных данных до иерархической генерации.

8. **По сравнению с плоскими VAE и CVAE**, иерархическая архитектура изучает более структурированные представления без необходимости явных меток обуславливания — иерархия обнаруживает разделение масштабов автоматически из данных.
