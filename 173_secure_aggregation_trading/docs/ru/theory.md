# Теория Secure Aggregation (SecAgg)

Secure Aggregation — это подкласс протоколов многосторонних вычислений (Multi-Party Computation, MPC), специально оптимизированный для эффективного суммирования весов нейронных сетей в федеративном обучении.

## Математическая основа: Аддитивное маскирование

Основная идея SecAgg заключается в том, что каждый клиент маскирует свой локальный вектор весов $x_i$ перед отправкой на сервер. Маски выбираются так, чтобы они сокращались при сложении.

Пусть у нас есть $n$ клиентов. Каждый клиент $i$ вычисляет маскированный вектор:
$$y_i = x_i + \sum_{j > i} s_{i,j} - \sum_{j < i} s_{j,i}$$

Где $s_{i,j}$ — это общее случайное число (маска), известное только клиентам $i$ и $j$.

### Свойства суммы
Когда сервер получает все маскированные векторы $y_i$ и суммирует их:
$$\sum_{i=1}^n y_i = \sum_{i=1}^n x_i + \sum_{i=1}^n \left( \sum_{j > i} s_{i,j} - \sum_{j < i} s_{j,i} \right)$$

В двойной сумме каждая пара масок $(i, j)$ встречается ровно два раза: один раз со знаком «плюс» (для клиента $i$) и один раз со знаком «минус» (для клиента $j$). В итоге все маски сокращаются:
$$\sum_{i=1}^n y_i = \sum_{i=1}^n x_i$$

Сервер получает точную сумму оригинальных весов, но для него каждое отдельное значение $y_i$ выглядит как случайный шум из-за неизвестных ему масок.

## Протокол Bonawitz et al. (2017)

В реальных условиях (например, в трейдинге через интернет) клиенты могут отключаться. Современный протокол SecAgg решает эту проблему через **Double Masking** и **Shamir's Secret Sharing**:

1. **Маска сессии ($s_i$)**: Каждый клиент добавляет свою уникальную маску.
2. **Маски пар ($s_{i,j}$)**: Добавляются для защиты от сговора сервера с частью клиентов.
3. **Общий секрет**: Если клиент отключается, оставшиеся клиенты могут помочь серверу восстановить его маску $s_i$ (но не его данные!), чтобы сервер мог «вычесть» её из общей суммы и корректно завершить агрегацию.

## Применение в трейдинге

Для хедж-фондов и проп-трейдинговых компаний SecAgg является критическим инструментом:
- **Защита стратегии**: Даже если центральный агрегатор взломан, злоумышленник не увидит веса отдельных фондов.
- **Минимизация утечек**: Доказано, что SecAgg математически защищает от атак реконструкции данных (Inference Attacks) со стороны сервера.
- **Coopetition**: Позволяет конкурентам безопасно объединять усилия для обучения на общих данных (например, обнаружение спуфинга или манипуляций на рынке).

Этот протокол требует дополнительных затрат на обмен ключами, но обеспечивает наивысший уровень приватности в федеративной среде.
