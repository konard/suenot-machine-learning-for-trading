# Глава 282: Контрастивное самообучение с предобучением для трейдинга

## 1. Введение

Финансовые временные ряды представляют фундаментальную проблему для обучения с учителем: размеченных данных мало, их получение дорого и зачастую субъективно. Один аналитик может обозначить период как «бычий режим», тогда как другой назовёт его «консолидацией». Контрастивное самообучение с предобучением полностью обходит эту проблему, обучая полезные представления на сырых, неразмеченных рыночных данных.

Основная идея проста, но мощна: если мы можем научить модель распознавать, когда два по-разному аугментированных вида одного и того же рыночного окна являются «одинаковыми», а когда два разных окна «различаются», модель неявно учится улавливать базовую структуру рынка — режимы волатильности, трендовые паттерны, динамику возврата к среднему — без единой метки.

В этой главе рассматриваются три основных фреймворка контрастивного обучения — SimCLR, MoCo и BYOL — адаптированные специально для финансовых временных рядов. Мы разрабатываем стратегии аугментации, сохраняющие семантическое содержание ценовых данных, реализуем полный пайплайн на Rust для производственного уровня производительности и демонстрируем downstream-приложения, включая обнаружение режимов с малым количеством примеров и обнаружение аномалий с использованием реальных данных криптовалют Bybit.

### Почему контрастивное обучение для финансов?

Традиционные ML-воркфлоу в финансах страдают от нескольких проблем, которые контрастивное предобучение напрямую решает:

1. **Дефицит меток**: Разметка рыночных режимов требует экспертной аннотации. Контрастивному обучению метки не нужны.
2. **Нестационарность**: Рынки меняются со временем. Предобученные представления лучше переносятся между режимами, чем вручную созданные признаки.
3. **Эффективность данных**: После предобучения downstream-задачи могут работать всего с 10-50 размеченными примерами.
4. **Качество признаков**: Контрастивные представления улавливают микроструктуру рынка, которую пропускают вручную спроектированные признаки.

## 2. Математические основы

### 2.1 Фреймворк контрастивного обучения

Для неразмеченного набора рыночных окон $\{x_1, x_2, \ldots, x_N\}$ контрастивное обучение выполняется в четыре шага:

1. **Аугментация**: Для каждого образца $x_i$ генерируем два аугментированных вида $\tilde{x}_i^{(1)}$ и $\tilde{x}_i^{(2)}$ с помощью стохастических преобразований $t \sim \mathcal{T}$.
2. **Кодирование**: Оба вида пропускаются через кодировщик $f_\theta$ для получения представлений $h_i^{(1)} = f_\theta(\tilde{x}_i^{(1)})$ и $h_i^{(2)} = f_\theta(\tilde{x}_i^{(2)})$.
3. **Проекция**: Представления отображаются через проекционную голову $g_\phi$: $z_i^{(1)} = g_\phi(h_i^{(1)})$ и $z_i^{(2)} = g_\phi(h_i^{(2)})$.
4. **Контрастивная функция потерь**: Притягивание позитивных пар $(z_i^{(1)}, z_i^{(2)})$ и отталкивание негативных пар.

### 2.2 SimCLR: Простое контрастивное обучение представлений

SimCLR использует нормализованную температурно-масштабированную перекрёстную энтропию (NT-Xent loss). Для мини-батча из $N$ образцов, дающих $2N$ аугментированных видов, определим сходство:

$$\text{sim}(z_i, z_j) = \frac{z_i^\top z_j}{\|z_i\| \|z_j\|}$$

Функция потерь NT-Xent для позитивной пары $(i, j)$:

$$\ell_{i,j} = -\log \frac{\exp(\text{sim}(z_i, z_j) / \tau)}{\sum_{k=1}^{2N} \mathbb{1}_{[k \neq i]} \exp(\text{sim}(z_i, z_k) / \tau)}$$

где $\tau$ — гиперпараметр температуры, контролирующий резкость распределения. Общая функция потерь усредняется по всем позитивным парам:

$$\mathcal{L}_{\text{SimCLR}} = \frac{1}{2N} \sum_{k=1}^{N} [\ell_{2k-1, 2k} + \ell_{2k, 2k-1}]$$

### 2.3 MoCo: Контраст с импульсом

MoCo решает проблему необходимости больших батчей в SimCLR, поддерживая обновляемую импульсом очередь негативных примеров. Используются два кодировщика:

- **Кодировщик запросов** $f_q$ с параметрами $\theta_q$, обновляемый градиентным спуском.
- **Кодировщик ключей** $f_k$ с параметрами $\theta_k$, обновляемый экспоненциальным скользящим средним:

$$\theta_k \leftarrow m \cdot \theta_k + (1 - m) \cdot \theta_q$$

где $m \in [0.99, 0.999]$ — коэффициент импульса.

### 2.4 BYOL: Bootstrap Your Own Latent

BYOL полностью исключает негативные пары, используя только позитивные пары с асимметричной архитектурой:

- **Онлайн-сеть**: кодировщик $f_\theta$, проектор $g_\theta$, предиктор $q_\theta$
- **Целевая сеть**: кодировщик $f_\xi$, проектор $g_\xi$ (без предиктора), обновляемая через импульс

Функция потерь — среднеквадратичная ошибка между L2-нормализованным предсказанием и целью:

$$\mathcal{L}_{\text{BYOL}} = \left\| \frac{q_\theta(z_\theta)}{\|q_\theta(z_\theta)\|_2} - \frac{z_\xi}{\|z_\xi\|_2} \right\|_2^2$$

### 2.5 Архитектура проекционной головы

Проекционная голова $g_\phi$ — двухслойный MLP:

$$g_\phi(h) = W_2 \cdot \sigma(W_1 \cdot h + b_1) + b_2$$

где $\sigma$ — нелинейность (ReLU или GELU). Исследования показывают, что представления $h$ (до проекции) превосходят проекции $z$ на downstream-задачах.

## 3. Стратегии аугментации для финансовых временных рядов

Качество контрастивных представлений критически зависит от стратегии аугментации. В отличие от изображений, где стандартны повороты и цветовой джиттер, финансовые временные ряды требуют предметно-ориентированных аугментаций, сохраняющих рыночную семантику.

### 3.1 Маскирование по времени

Случайное маскирование непрерывных сегментов временного ряда заменой на нули или среднее значение:

$$\tilde{x}_t = \begin{cases} 0 & \text{если } t \in [t_s, t_s + L] \\ x_t & \text{иначе} \end{cases}$$

### 3.2 Масштабирование амплитуды

Масштабирование значений случайным коэффициентом из узкого диапазона:

$$\tilde{x}_t = \alpha \cdot x_t, \quad \alpha \sim \text{Uniform}(0.8, 1.2)$$

### 3.3 Гауссовский джиттер

Добавление небольшого гауссовского шума:

$$\tilde{x}_t = x_t + \epsilon_t, \quad \epsilon_t \sim \mathcal{N}(0, \sigma^2)$$

### 3.4 Временная деформация

Применение нелинейного временного искажения для симуляции различных частот дискретизации.

### 3.5 Дропаут каналов

Для многопризнаковых входов (OHLCV) случайное отключение одного или нескольких каналов.

### Стратегия композиции

Эффективная аугментация комбинирует несколько преобразований:

$$\mathcal{T} = \text{TimeMask} \circ \text{MagnitudeScale} \circ \text{GaussianJitter}$$

Каждая аугментация применяется с вероятностью 0.5.

## 4. Downstream-приложения

### 4.1 Обнаружение режимов с малым количеством примеров

После предобучения замораживаем кодировщик $f_\theta$ и обучаем линейный классификатор на небольшом размеченном датасете:

$$\hat{y} = \text{softmax}(W \cdot f_\theta(x) + b)$$

С всего 20 размеченными примерами на режим контрастивный кодировщик может обнаруживать бычьи/медвежьи/боковые режимы с точностью 75-85%.

### 4.2 Обнаружение аномалий

Вычисление представлений для эталонного набора «нормальных» рыночных окон. Новые окна помечаются как аномальные, если их представление далеко от эталонного распределения:

$$\text{anomaly\_score}(x) = \min_{x_r \in \text{ref}} \|f_\theta(x) - f_\theta(x_r)\|_2$$

### 4.3 Поиск аналогий

Нахождение исторических периодов, наиболее похожих на текущее состояние рынка:

$$x^* = \arg\min_{x_h \in \text{history}} \|f_\theta(x_{\text{current}}) - f_\theta(x_h)\|_2$$

## 5. Реализация на Rust

Наша реализация на Rust предоставляет полный пайплайн контрастивного обучения, пригодный для продакшена. Ключевые компоненты:

- **`Augmenter`**: Настраиваемый пайплайн аугментации с поддержкой маскирования, масштабирования, джиттера и композиции.
- **`Encoder`**: Простой кодировщик прямого прохода, отображающий окна временных рядов в фиксированные представления.
- **`ProjectionHead`**: Двухслойный MLP для проекции представлений в контрастивное пространство.
- **`NtXentLoss`**: Вычисление контрастивной функции потерь NT-Xent.
- **`MomentumEncoder`**: Кодировщик с импульсным обновлением в стиле MoCo с очередью негативных примеров.
- **`LinearProbe`**: Линейный классификатор для оценки качества представлений на downstream-задачах.
- **`BybitClient`**: Асинхронный клиент для получения данных с биржи Bybit.

## 6. Интеграция с Bybit

Используется Bybit V5 API для получения исторических данных свечей (kline):

```
GET https://api.bybit.com/v5/market/kline?category=spot&symbol=BTCUSDT&interval=15&limit=200
```

Возвращаются данные OHLCV, которые мы предобрабатываем в окна для контрастивного обучения:

1. **Загрузка** 200 свечей 15-минутных данных BTCUSDT.
2. **Нормализация** с помощью z-score нормализации по каждому окну.
3. **Разбиение** на перекрывающиеся сегменты по 20 баров.
4. **Аугментация** каждого окна для создания позитивных пар.
5. **Кодирование** и вычисление контрастивной функции потерь для проверки пайплайна.

## 7. Ключевые выводы

1. **Контрастивное предобучение изучает структуру рынка без меток.** Обучая модель распознавать аугментированные виды одного рыночного окна, мы получаем представления, улавливающие режимы, паттерны волатильности и динамику трендов.

2. **Дизайн аугментаций критически важен.** Финансовые аугментации должны сохранять семантическое содержание: маскирование по времени, масштабирование амплитуды и гауссовский джиттер эффективны; случайное перемешивание или крупномасштабная деформация разрушают сигнал.

3. **SimCLR — простейший, MoCo — экономичный по памяти, BYOL — без негативных пар.** Выбирайте в зависимости от инфраструктуры.

4. **Проекционная голова используется только при предобучении.** Downstream-задачи используют представления кодировщика напрямую.

5. **Обучение с малым количеством примеров становится реальным.** С контрастивным предобучением обнаружение режимов работает с 20-50 размеченными примерами.

6. **Обнаружение аномалий — естественная downstream-задача.** Пространство представлений естественно кластеризует похожие рыночные состояния.

7. **Rust обеспечивает производственный уровень производительности.** Модульная реализация обрабатывает загрузку данных, аугментацию, кодирование и оценку с гарантиями безопасности и скорости Rust.

8. **Настройка температуры имеет значение.** Температура NT-Xent $\tau$ контролирует сложность контрастивной задачи. Для финансовых данных $\tau \in [0.05, 0.1]$ обычно работает хорошо.
