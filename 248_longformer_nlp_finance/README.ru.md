# Глава 248: Longformer для финансового NLP

## Введение

Финансовый анализ регулярно требует обработки длинных документов: годовых отчётов (10-K), стенограмм конференц-звонков по результатам, проспектов, нормативных документов и многостраничных аналитических записок. Стандартные модели трансформеров, такие как BERT, ограничены 512 токенами, что вынуждает практиков обрезать или разбивать эти документы на части, теряя межсекционный контекст. Longformer, представленный Beltagy, Peters и Lo (2020), решает эту проблему, заменяя квадратичный механизм самовнимания комбинацией локального скользящего оконного внимания и специфического для задачи глобального внимания, обеспечивая эффективную обработку последовательностей до 4096 токенов (или длиннее при соответствующей конфигурации).

Для финансовых приложений это расширенное контекстное окно является трансформационным. Один отчёт 10-K может содержать более 50 000 слов, и критически важная информация (факторы риска, обсуждение руководства, финансовые отчёты) распределена по всему документу. Аналитику, стремящемуся классифицировать общий тон документа, обнаружить существенные раскрытия рисков или извлечь прогнозные заявления, необходима модель, способная одновременно обращать внимание на удалённые части документа. Паттерн внимания Longformer делает это выполнимым без запретительной стоимости памяти полного квадратичного внимания.

В этой главе представлена полная система применения Longformer к финансовым задачам NLP. Мы рассмотрим механизм внимания, ключевые адаптации для финансового текста и рабочую реализацию на Rust, подключённую к криптовалютной бирже Bybit для анализа на основе тональности в реальном времени.

## Ключевые концепции

### Сложность внимания в трансформерах

Стандартное самовнимание вычисляет попарные взаимодействия между всеми токенами последовательности. Для последовательности длины $n$ это требует $O(n^2)$ времени и памяти. При 512 токенах это управляемо, но при 4096 токенах стоимость возрастает в 64 раза, а при 16384 — в 1024 раза. Это квадратичное масштабирование является фундаментальным узким местом, препятствующим обработке длинных документов стандартными трансформерами.

Оценка внимания между запросом $q_i$ и ключом $k_j$ в стандартном самовнимании:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

где $Q, K, V \in \mathbb{R}^{n \times d}$ и произведение $QK^T$ имеет сложность $O(n^2)$.

### Паттерн внимания Longformer

Longformer заменяет полное самовнимание разреженным паттерном внимания, объединяющим три типа внимания:

**1. Скользящее оконное внимание (локальное)**

Каждый токен обращает внимание на фиксированное окно из $w$ соседних токенов с каждой стороны. При размере окна $w = 256$ каждый токен обращает внимание на 512 окружающих токенов. Это захватывает локальный контекст и синтаксическую структуру со сложностью $O(n \times w)$.

$$\text{SlidingAttn}(i) = \{j : |i - j| \leq w\}$$

**2. Расширенное скользящее оконное внимание**

Для увеличения рецептивного поля без увеличения вычислений расширенное внимание вводит промежутки размера $d$ (фактор расширения) в паттерн скользящего окна. При расширении $d = 2$ и окне $w = 256$ эффективное рецептивное поле удваивается при сохранении того же количества позиций внимания:

$$\text{DilatedAttn}(i) = \{j : |i - j| \leq w \times d \text{ и } (i - j) \mod d = 0\}$$

**3. Глобальное внимание**

Выбранные токены (например, токен [CLS] или токены, соответствующие ключевым сущностям) обращают внимание на все токены последовательности, и все токены обращают внимание на них. Это обеспечивает поток информации по всему документу:

$$\text{GlobalAttn}(i) = \{1, 2, \ldots, n\} \quad \text{для назначенных глобальных токенов}$$

Общая сложность составляет $O(n \times w + n \times g)$, где $g$ — количество токенов глобального внимания, что линейно по $n$ при фиксированных $w$ и $g$.

### Предобучение и дообучение

Longformer инициализируется из контрольных точек RoBERTa и продолжает предобучение на длинных документах с использованием маскированного языкового моделирования (MLM). Позиционные эмбеддинги расширяются с 512 до 4096 путём восьмикратного копирования существующих эмбеддингов. При дообучении для последующих задач:

- **Классификация документов**: токен [CLS] получает глобальное внимание, и его представление используется для классификации.
- **Классификация токенов (NER)**: все токены используют локальное внимание; диапазоны сущностей классифицируются на основе их контекстуальных представлений.
- **Ответы на вопросы**: токены вопроса получают глобальное внимание для обеспечения рассуждений по документу.

Функция потерь при дообучении зависит от задачи. Для классификации:

$$\mathcal{L} = -\sum_{i=1}^{N} \sum_{c=1}^{C} y_{i,c} \log(\hat{y}_{i,c})$$

где $C$ — количество классов и $\hat{y}_{i,c}$ — предсказанная вероятность для класса $c$.

### Позиционное кодирование для длинных последовательностей

Longformer расширяет позиционные эмбеддинги BERT/RoBERTa для обработки более длинных последовательностей. Абсолютные позиционные эмбеддинги реплицируются для покрытия расширенного диапазона:

$$PE_{\text{long}}(pos) = PE_{\text{short}}(pos \mod L_{\text{short}})$$

где $L_{\text{short}}$ — исходная максимальная позиция (512). Во время продолженного предобучения эти реплицированные эмбеддинги дообучаются для изучения позиционно-специфических паттернов расширенного диапазона.

## Подходы машинного обучения

### Классификация тональности на уровне документа

Основная задача финансового NLP для Longformer — классификация тональности целых документов — стенограмм конференц-звонков, аналитических отчётов или новостных статей — без обрезки.

Для документа, токенизированного в $\{x_1, x_2, \ldots, x_n\}$ с $n \leq 4096$, Longformer кодирует последовательность, используя свой смешанный паттерн внимания. Представление токена [CLS] $\mathbf{h}_{\text{CLS}} \in \mathbb{R}^d$ подаётся через классификационную головку:

$$\hat{y} = \text{softmax}(\mathbf{W}\mathbf{h}_{\text{CLS}} + \mathbf{b})$$

где $\mathbf{W} \in \mathbb{R}^{C \times d}$ и $\mathbf{b} \in \mathbb{R}^C$. Классы обычно включают положительную, отрицательную и нейтральную тональность.

### Распознавание именованных сущностей в финансовых документах

Longformer превосходно справляется с финансовым NER, поскольку контекст сущностей часто охватывает длинные расстояния. Например, название компании, упомянутое на первой странице 10-K, может быть релевантным для фактора риска, обсуждаемого на десятой странице. Модель использует скользящее оконное внимание для локального обнаружения сущностей и глобальное внимание на заголовках разделов для поддержания контекста на уровне документа.

Каждый токен $x_i$ классифицируется в BIO-теги:

$$\hat{y}_i = \text{softmax}(\mathbf{W}_{\text{ner}}\mathbf{h}_i + \mathbf{b}_{\text{ner}})$$

Типы сущностей, релевантные для финансов, включают: ORG (организации), MONEY (денежные суммы), PERCENT (проценты), DATE (даты), PRODUCT (финансовые инструменты) и EVENT (рыночные события).

### Обнаружение факторов риска

Нормативные документы содержат раскрытия рисков, которые являются существенными для инвестиционных решений. Longformer может классифицировать каждый абзац или раздел как содержащий или не содержащий фактор риска, используя расширенный контекст для понимания того, как риски связаны с общим бизнесом компании:

$$P(\text{risk} | \text{paragraph}_i) = \sigma(\mathbf{w}^T \mathbf{h}_i + b)$$

где $\mathbf{h}_i$ — представление абзаца Longformer, полученное путём пулинга по его токеновым представлениям.

## Инженерия признаков

### Признаки на уровне токенов

Финансовые документы содержат доменно-специфические токены, требующие тщательной обработки:

- **Финансовые числа**: денежные значения, проценты, коэффициенты. Они должны быть нормализованы (например, "$1.2B" и "$1,200M" должны быть эквивалентны).
- **Временные выражения**: фискальные кварталы, межгодовые ссылки. Они привязывают документ ко времени.
- **Юридические/нормативные термины**: "существенное неблагоприятное воздействие", "непрерывность деятельности", "форс-мажор". Они несут специфическую юридическую нагрузку.
- **Индикаторы тональности**: "превысил ожидания", "встречные ветры", "устойчивый рост". Словарь в стиле FinBERT здесь особенно ценен.

### Признаки структуры документа

Финансовые документы имеют явную структуру, которую можно использовать:

- **Заголовки разделов**: отображаются на токены глобального внимания, чтобы модель могла маршрутизировать информацию между разделами.
- **Маркеры таблиц**: финансовые таблицы содержат критически важные количественные данные; обозначаются их границы.
- **Ссылки на сноски**: связывают содержание сносок с основным текстом через потенциально тысячи токенов.

### Агрегированные признаки тональности

Для торговых приложений тональность на уровне документа должна быть агрегирована в действенные сигналы:

- **Оценка тональности**: непрерывное значение в $[-1, 1]$ от классификационной головки
- **Моментум тональности**: изменение тональности между последовательными документами $\Delta S_t = S_t - S_{t-1}$
- **Межнаходочный консенсус**: средняя тональность по нескольким источникам для одного актива
- **Сюрприз тональности**: отклонение от ожидаемой тональности $S_t - \mathbb{E}[S_t | S_{t-1}, \ldots, S_{t-k}]$

## Применения

### Анализ конференц-звонков по результатам

Стенограммы конференц-звонков содержат 5000-15000 слов, что значительно превышает возможности BERT. Longformer может:

1. **Тональность полной стенограммы**: классифицировать общий тон звонка без обрезки, улавливая взаимосвязь между подготовленными заявлениями и секцией вопросов и ответов.
2. **Анализ на уровне разделов**: применить глобальное внимание к маркерам разделов (заявления CEO, заявления CFO, Q&A) для сравнения тона между разделами.
3. **Обнаружение прогнозных заявлений**: идентифицировать и классифицировать предложения о будущих ожиданиях, распределённые по стенограмме.

### Анализ нормативных документов

Документы 10-K и 10-Q содержат критически важную информацию для фундаментального анализа:

- **Извлечение факторов риска**: идентификация новых или изменённых раскрытий рисков по сравнению с предыдущими документами.
- **Обсуждение и анализ руководства (MD&A)**: извлечение интерпретации руководством финансовых результатов и прогнозов.
- **Обнаружение существенных событий**: выделение разделов, описывающих события, которые могут повлиять на цену акций.

### Анализ новостей криптовалютного рынка

Для криптовалютных рынков длинный контент включает:

- **Анализ whitepaper**: оценка технической сложности и осуществимости новых проектов.
- **Предложения по управлению**: оценка вероятного воздействия изменений протокола на стоимость токена.
- **Агрегация тредов**: объединение нескольких связанных новостных статей или тредов социальных сетей в единый анализ с длинным контекстом.

## Реализация на Rust

Наша реализация на Rust предоставляет упрощённый набор инструментов для анализа текста в стиле Longformer для финансового NLP:

### SlidingWindowAttention

Структура `SlidingWindowAttention` реализует основной механизм локального внимания. Она вычисляет оценки внимания в фиксированном окне вокруг каждой позиции токена, используя точечное произведение внимания с масштабированием. Реализация обрабатывает граничные случаи на краях последовательности, где окно обрезается.

### GlobalAttentionMask

Структура `GlobalAttentionMask` управляет тем, какие позиции токенов получают глобальное внимание. Она предоставляет методы для назначения токена [CLS], заголовков разделов и токенов сущностей как позиций глобального внимания.

### LongformerEncoder

`LongformerEncoder` объединяет скользящее оконное и глобальное внимание в полный слой кодирования. Он обрабатывает эмбеддинги токенов через смешанный паттерн внимания, применяет нормализацию слоя и производит контекстуализированные представления для последующей классификации.

### SentimentClassifier

`SentimentClassifier` реализует логистическую регрессию по признакам в стиле Longformer для бинарной классификации тональности. Он принимает векторы признаков, полученные из текстового анализа, и выводит предсказание тональности с уверенностью.

### BybitClient

Структура `BybitClient` обеспечивает асинхронный HTTP-доступ к Bybit V5 API. Она получает данные kline (свечей) из эндпоинта `/v5/market/kline` для контекста рыночных данных наряду с сигналами, полученными из NLP.

## Интеграция с Bybit API

Реализация подключается к REST API Bybit V5 для комбинирования сигналов тональности NLP с рыночными данными:

- **Эндпоинт Kline** (`/v5/market/kline`): предоставляет OHLCV-данные свечей для корреляции сигналов тональности с движениями цены.
- **Эндпоинт книги заявок** (`/v5/market/orderbook`): предоставляет контекст микроструктуры рынка для понимания того, как тональность транслируется в поток ордеров.

Торговая стратегия комбинирует NLP-сигналы с ценовыми данными: когда анализ тональности Longformer обнаруживает сильный положительный или отрицательный сигнал в длинном финансовом документе, система проверяет текущие рыночные условия через Bybit API перед генерацией торговой рекомендации.
