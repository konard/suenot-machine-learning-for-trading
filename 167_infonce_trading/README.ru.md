# Глава 167: InfoNCE для трейдинга

## Обзор

**InfoNCE (Information Noise-Contrastive Estimation)** — это контрастивная функция потерь, предложенная в статье Contrastive Predictive Coding (van den Oord et al., 2018). Она максимизирует взаимную информацию между обученным представлением и данными, которые оно кодирует, различая «позитивный» образец от набора «негативных» отвлекающих примеров.

В то время как Глава 166 была посвящена полной архитектуре CPC (энкодер + авторегрессионная модель), эта глава выделяет **InfoNCE loss как самостоятельный** универсальный инструмент для обучения торговых представлений. InfoNCE может применяться в любом сценарии, где необходимо обучить эмбеддинги, отражающие сходство — между временными окнами, между активами или между рыночными условиями.

## Математические основы

### Максимизация взаимной информации

Цель InfoNCE — максимизировать нижнюю границу взаимной информации $I(X; C)$ между данными $X$ и их контекстом $C$:

$$\mathcal{L}_{\text{InfoNCE}} = -\mathbb{E}\left[\log \frac{f_k(x_{t+k}, c_t)}{\sum_{x_j \in X} f_k(x_j, c_t)}\right]$$

где:
- $f_k(x, c) = \exp(z_x^\top W_k c)$ — функция оценки (лог-билинейная модель)
- $x_{t+k}$ — **позитивный** образец (реальное будущее)
- $\{x_j\}$ содержит один позитивный и $N-1$ **негативных** образцов (случайные отвлекающие примеры)
- $c_t$ — контекстный вектор в момент времени $t$

### Связь с кросс-энтропией

На практике InfoNCE сводится к **softmax кросс-энтропии** по индексу позитивного образца:

$$\mathcal{L} = -\log \frac{\exp(\text{sim}(q, k_+) / \tau)}{\sum_{i=0}^{N} \exp(\text{sim}(q, k_i) / \tau)}$$

где $\tau$ — гиперпараметр температуры, контролирующий резкость распределения.

### Значение температуры

- **Низкая $\tau$** (напр., 0.05): Модель должна делать очень уверенные различия. Подходит для хорошо разделённых классов.
- **Высокая $\tau$** (напр., 1.0): Модель распределяет вероятность более равномерно. Полезно, когда категории пересекаются.
- В трейдинге $\tau \in [0.07, 0.5]$ работает хорошо. Рынки имеют размытые границы между режимами, поэтому предпочтительны умеренные температуры.

## Применения в трейдинге

### 1. Определение схожести рыночных режимов

Обучение энкодера, чтобы окна одного рыночного режима (напр., «высоковолатильный восходящий тренд») были ближе в пространстве эмбеддингов, чем окна разных режимов.

### 2. Поиск пар между активами

Использование InfoNCE для определения активов, которые движутся схожим образом при определённых условиях, для динамического парного трейдинга или ротации секторов.

### 3. Сопоставление временных паттернов

Создание эмбеддингов исторических окон и использование InfoNCE для поиска прошлых периодов, наиболее похожих на текущее состояние рынка.

### 4. Представление потока ордеров

Обучение компактных представлений снапшотов стакана, где схожие состояния ликвидности сгруппированы вместе.

## Архитектура

```
         ┌──────────────┐
   x_i → │   Энкодер    │ → z_i (якорь)
         │  (1D-CNN)    │
         └──────────────┘
                │
                ▼
         ┌──────────────┐
         │  InfoNCE     │ ← z_+ (позитивный), z_1...z_N (негативные)
         │  Loss        │
         └──────────────┘
                │
                ▼
         Максимизировать similarity(z_i, z_+)
         Минимизировать similarity(z_i, z_j) для j ≠ +
```

## Ключевые отличия от стандартного CPC (Глава 166)

| Аспект | CPC (Гл. 166) | InfoNCE (Гл. 167) |
|--------|---------------|-------------------|
| Область | Полная архитектура | Фокус на функции потерь |
| Негативные примеры | Другие примеры из батча | Настраиваемая стратегия |
| Контекст | Авторегрессионный GRU | Любой якорный эмбеддинг |
| Температура | Неявная | Явный параметр $\tau$ |
| Применение | Предсказание во времени | Общее обучение сходства |
